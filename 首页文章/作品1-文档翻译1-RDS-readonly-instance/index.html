    创建与配置云数据库 (RDS) 只读实例

    功能概述： 只读实例（Read-only Instance）主要用于分担主实例的读取压力。在业务场景出现“读多写少”时，通过创建多个只读实例并配置读写分离连接地址，可以大幅提升数据库系统的整体吞吐量和响应速度。

    应用限制与前提条件：

    • 主实例状态： 仅当主实例处于“运行中”状态且未进行存储空间缩容时，方可创建只读实例。
    • 网络环境： 只读实例必须与主实例处于同一虚拟私有云（VPC）内，以确保内网互通及低延迟。
    • 数据一致性： 由于采用异步复制机制，只读实例与主实例之间可能存在毫秒级的同步延迟。

    配置步骤：

    1. 发起创建： 登录数据库管理控制台。在“实例列表”中找到目标主实例，点击其右侧操作列的“更多” > “创建只读实例”。
    2. 规格选型：
      • 选择只读实例的计算规格（CPU 与内存）。建议只读实例的规格不低于主实例，以防止因同步压力过大导致延迟增加。
      • 设置存储容量。存储空间将默认与主实例保持一致，且支持随业务增长自动扩容。
    3. 配置读写分离：
      • 进入“连接管理”页面，点击“开通读写分离”。
      • 设置“延迟阈值”。若只读实例的延迟超过该设定值（例如 30 秒），系统将自动停止向该实例分发流量，以防止读取到过期的旧数据。
    4. 权重分配： 手动设置各只读实例的流量权重。若权重设为 0，则该实例仅作为备份，不承担前端查询业务。

    安全警告：

    • 不可逆操作： 只读实例一旦创建，无法直接将其转换为独立的主实例。
    • 备份说明： 只读实例不支持开启自动备份功能。若需进行数据恢复，请操作主实例的备份集。

    故障排查：

    如果发现只读实例状态显示为“同步异常”，请检查主实例是否存在长事务（Long-running transactions）导致日志堆积。建议优化慢查询 SQL 或升级只读实例规格。

    Create and Configure RDS Read-only Instance

    Overview:

    Read-only Instances offload query pressure from the primary instance. In read-heavy scenarios, you can create multiple read-only instances and configure read/write splitting to increase system throughput and response speeds.

    Prerequisites:

    • Status: The primary instance must be in the "running" status.
    • Storage: No storage shrinking is in process on the primary instance.
    • Network Environment: Read-only Instances and the primary instance must be in the same virtual private cloud (VPC) to ensure internal connectivity and low latency.
    • Data Consistency: Due to asynchronous replication mechanism, a synchronization latency of several milliseconds may occur between the read-only Instances and the primary instance.

    Configuration Steps:

    1. Initiate Creation: Log in to the RDS console> Find the primary instance in the "instances list">Click "more">"Create a read-only instance".
    2. Select Specifications:
      • Computing: Choose the CPU and memory. Ideally, use a configuration that matches or exceeds the primary instance to prevent latency.
      • Storage: By default, storage matches the primary instance and supports Auto-scaling.
    3. Configure Read/Write Splitting:
      • On the Connection Management page, click "Enable Read/Write Splitting".
      • Set a Latency Threshold. If the latency exceeds the threshold (e.g., 30 seconds), the system stops routing traffic to that instance to prevent users from reading stale data.
    4. Assign Weights: Manually set the traffic weight for each instance. A weight of zero indicates that the instance acts as a standby and does not process queries.

    Warning:

    • Irreversible: A read-only instance cannot be promoted to a standalone primary instance.
    • Backups: Read-only instances do not support automatic backups. Perform data recovery using the primary instance’s backup sets.

    Troubleshooting:

    If the instance status is “synchronous exception”, check the primary instance for long-running transactions.
    Suggested Action: Optimize slow SQL query or upgrade the read-only instance's specifications.
