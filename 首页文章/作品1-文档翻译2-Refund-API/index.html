    技术文档翻译2：支付网关退款 API

    本作品展示如何将 API 技术文档从中文翻译为符合国际标准的英文开发者文档。

    英专生技术写作作品 · 专八/三笔

    左右对照

    🔍 中文原文

    接口名：发起退款请求 (Initiate Refund)

    功能描述
    当订单发生退货或取消时，商户系统需调用本接口向支付网关申请退款。支持部分退款（Partial Refund）和全额退款（Full Refund）。退款资金通常会原路返回至用户的支付账户。

    请求信息

    • URL: https://api.gateway.com/v3/payments/{transaction_id}/refund
    • Method: POST
    • 认证方式： Bearer Token（需在 HTTP Header 中包含 API Secret Key）

    请求参数 (Body)

    参数 类型 必填 说明
    refund_amount Decimal 是 申请退款的金额。该金额不能大于订单的可退款剩余余额。
    reason String 是 退款原因说明，字数限制为 10-200 字。该信息可能会展示给最终用户。
    out_refund_no String 是 商户系统内部自定义的退款单号，在商户侧必须保证全局唯一。
    notify_url String 否 异步通知地址。退款成功后，系统将通过该 URL 向商户服务器发送回调通知。若不填，则不发送通知。
    metadata Object 否 扩展字段。商户可以传递自定义的键值对信息，用于内部账务对齐。

    接口逻辑约束

    • 幂等性控制： 本接口支持幂等性。如果使用相同的 out_refund_no 重复调用，系统将直接返回第一次处理的结果，不会重复扣款。
    • 退款时效： 仅支持对 12 个月内创建的订单发起退款，超过该期限的交易请通过线下流程处理。

    常见响应状态码

    状态码 说明
    201 Created退款申请已成功受理。
    400 Bad Request请求参数校验失败（例如金额格式错误）。
    403 ForbiddenAPI Key 无效或权限不足。
    409 Conflict存在冲突的退款请求（例如同一笔交易已有正在处理中的退款）。
    422 Unprocessable Entity余额不足，无法完成退款操作。

    ✏️ 英文译文

    API: Initiate Refund

    Description
    The merchant system uses this API to request a refund from the payment gateway when an order is returned or canceled. The API supports both partial refund and full refund. Refunds are typically returned to the user's original payment account.

    Request Information

    • URL: https://api.gateway.com/v3/payments/{transaction_id}/refund
    • Method: POST
    • Authentication: Bearer Token (API Secret Key must be included in the HTTP Header)

    Request Parameters (Body)

    Parameter Type Required Description
    refund_amount Decimal Yes The amount to refund. This amount cannot exceed the remaining refundable balance of the order.
    reason String Yes Description of the refund (10-200 characters). This information may be visible to end users.
    out_refund_no String Yes A unique identifier for the refund, defined by the merchant system. Must be globally unique within the merchant's system.
    notify_url String No The URL for asynchronous notification. Upon successful refund, the system sends a callback notification to the merchant server via this URL. If omitted, no notification is sent.
    metadata Object No A set of key-value pairs used for internal accounting alignment, defined by the merchant.

    Constraints

    • Idempotency: The API is idempotent. If a request is submitted multiple times with the same out_refund_no, the system returns the initial result and does not process the refund again.
    • Refund Window: The API supports refunds for orders placed within the last 12 months. For orders exceeding this period, use offline processes.

    Response Status Codes

    Status Code Description
    201 CreatedThe refund request has been successfully processed.
    400 Bad RequestInvalid parameters (e.g., incorrect amount format).
    403 ForbiddenInvalid API Key or insufficient permissions.
    409 ConflictThe request conflicts with the current status of the resource (e.g., a refund for the same order is already in progress).
    422 Unprocessable EntityInsufficient balance to complete the refund.

    翻译说明

    维度 原文问题 优化方式

    术语 “幂等性” 直接使用 保留 “Idempotency”，技术文档标准术语
    一致性 状态码说明中英文对照 统一为英文，保持 API 文档惯例
    可读性 部分长句可简化 拆分为更短的句子，主动语态
